6. R-1 SUMMARY - Sequence Recall production authentication
--------------------------------------------------------------------------------
Problem (pre-existing):
  The only auth path was a dev/mock session fetched from a mock-user service.
  There was no production way to receive the player's JWT, and the mock import
  was statically bundled (i.e. shipped to production).

Implementation:
  - NEW src/services/sessionBootstrap.ts
      * bootstrapAuthFromUrl(): Promise<boolean>
      * Reads a launch token from BOTH the URL query string and the hash
        fragment, accepting common key spellings:
          token / auth_token / authToken / sessionToken
          expiresAt / expires_at / exp
      * Persists it via storage.setSecure(STORAGE_KEYS.AUTH_TOKEN /
        AUTH_EXPIRES_AT), so httpClient injects `Authorization: Bearer <jwt>`.
      * Immediately strips the auth params from the URL using
        window.history.replaceState (search + hash) so the token is not left
        in the address bar / history / referer.
      * Returns true iff a token was found and stored.

  - src/hooks/useAuthGate.ts
      * Removed the static `import { fetchDevSession }` and the dev-session
        helpers.
      * New ensureSession() decision flow:
            if (await hasStoredToken()) return;                 // already authed
            if (await bootstrapAuthFromUrl()) return;           // production path
            if (import.meta.env.DEV) { await getOrMintDevSession(stageId); return; }
            throw new Error('Missing authentication token. Launch the game from
                             the ZUBACO platform.');            // prod, no token
      * The dev session is minted via a dynamic `await import('@services/authService')`,
        so the mock path is code-split and excluded from the production bundle.

  - src/features/sequence-recall/components/SequenceRecallGameShell.tsx
      * Removed the static fetchDevSession import (and its TODO).
      * The 409 session-recovery branch is now gated:
            if (import.meta.env.DEV && !isRetry && err.statusCode === 409) { ... }
        and loads fetchDevSession via dynamic import, so it never runs in prod.

Production contract:
  The host platform launches the game with a signed JWT in the launch URL.
  This is the defined integration contract; the host-side wiring lives outside
  this repository.

7. R-2 SUMMARY - Sequence Recall clean-build hardening
--------------------------------------------------------------------------------
Goal: `npm ci && npm run build` GREEN from a pristine checkout. A clean install
(TypeScript resolving to 5.9.3) surfaced 15 compile errors plus a build-time
PostCSS failure. All resolved:

  (a) 6 test-file errors - `screen` / `waitFor` are not re-exported by
      @testing-library/react v16. Fix: added devDependency
      "@testing-library/dom": "^10.4.0" (its canonical home). Affected:
      button.test.tsx, useLeaderboard.test.tsx, SequenceBoard.test.tsx,
      SequenceRecallGameShell.test.tsx, uiComponents.test.tsx,
      useAnimatedNumber.test.tsx.

  (b) 3 errors in src/utils/encryption.ts - TS 5.9 tightened BufferSource /
      ArrayBufferLike so Uint8Array<ArrayBufferLike> is no longer accepted by
      WebCrypto. Fix: added a small toCryptoInput() helper that returns a fresh
      ArrayBuffer-backed copy, wrapping the importKey/encrypt/decrypt inputs.

  (c) 5 unused-symbol errors (noUnusedLocals / noUnusedParameters):
        - Confetti.tsx          : removed unused `useCallback` import
        - DailyChallenge.tsx    : `const [daily] = useState(...)` (dropped setter)
        - LevelSelector.tsx     : `const [levels] = useState(...)` (dropped setter)
        - HomePage.tsx          : `const [showConfetti] = useState(false)` and
                                  removed a dead handlePause useCallback block

  (d) BUILD-TIME failure - `[vite:css] Failed to load PostCSS config ...
      Unexpected token '<BOM>'`. Root cause: a PRE-EXISTING UTF-8 BOM
      (EF BB BF) at the top of package.json which postcss-load-config's JSON
      parser cannot handle. Confirmed pre-existing (git diff showed only the
      single @testing-library/dom insertion). Fix: rewrote package.json as
      UTF-8 without BOM (first bytes now 7B 0A 20 = `{`, LF, space).

8. R-3 SUMMARY - Pattern Survival roundTimings end-to-end
--------------------------------------------------------------------------------
The Pattern Survival backend already accepts and analyzes per-round input
timings (Phase 1), but the frontend never sent them, so the anti-cheat path
was dormant. Phase 1B closes the loop:

  - src/features/pattern/hooks/usePatternGame.ts
      * Added refs roundTimingsRef (number[][]) and currentRoundTapsRef (number[]).
      * startGame: reset both to [].
      * tapCell: capture tapTime = Math.round(performance.now()); a wrong tap
        discards the current round's taps; a valid tap pushes tapTime; on round
        completion the round's taps are appended to roundTimingsRef and the
        current buffer reset.
      * Exposed getRoundTimings(): number[][].

  - src/features/pattern/hooks/useGameSession.ts
      * submitGame() now accepts an optional 4th arg roundTimings?: number[][]
        and adds it to the payload only when non-empty (fully backward
        compatible - no API break).

  - src/features/pattern/components/GamePage.tsx
      * handleSubmit() passes getRoundTimings() into submitGame().

Backend (unchanged, Phase 1): submit-game.dto.ts validates
roundTimings?: number[][] (bounded); game.service.ts feeds
analyzeInputTiming(timings.slice(0, verifiedRounds).flat()) when perfect rounds
are claimed, voiding the perfect bonus and flagging suspicious cadence.
