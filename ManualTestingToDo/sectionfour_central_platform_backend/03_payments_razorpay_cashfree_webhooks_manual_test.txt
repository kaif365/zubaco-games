[ ] TC-01: RAZORPAY PAYMENT SUCCESS WEBHOOK (`payment.captured`)
    - Action: Post Razorpay webhook payload with valid `X-Razorpay-Signature` HMAC-SHA256 header.
    - Expected Result:
      * Signature is verified with `RAZORPAY_WEBHOOK_SECRET`.
      * Transaction updates from `PENDING` to `SUCCESS`.
      * Player's `depositBalance` is credited with exact amount (e.g. ₹500).
      * Webhook responds with HTTP 200 `{ "status": "ok" }`.

[ ] TC-02: DUPLICATE / RETRIED WEBHOOK REPLAY (CRITICAL P0 IDEMPOTENCY)
    - Action: Re-send the exact same webhook payload 3 times (simulating Razorpay network retry).
    - Expected Result:
      * Redis idempotency key and database transaction state check identify the duplicate payment ID.
      * Webhook returns HTTP 200 immediately without crediting the wallet twice.
      * Wallet balance increases by ₹500 ONLY ONCE (zero balance duplication leakage).

[ ] TC-03: INVALID HMAC SIGNATURE REJECTION (SECURITY P0)
    - Action: Tamper with webhook payload body or send garbage signature header `X-Razorpay-Signature: fake_signature`.
    - Expected Result:
      * Request is rejected with HTTP 400 "Invalid signature".
      * Wallet is NOT credited.
      * Security audit warning logged with source IP.

[ ] TC-04: PAYMENT FAILED WEBHOOK (`payment.failed`)
    - Action: Post failure callback from gateway.
    - Expected Result:
      * Transaction marked as `FAILED`.
      * Wallet balance remains unchanged.
      * User mobile app notifies player of deposit failure.
