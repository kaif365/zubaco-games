[ ] TC-02: TOURNAMENT ENTRY FEE DEDUCTION PRECEDENCE (CRITICAL P0)
    - Action: User has ₹20 Bonus, ₹30 Deposit, ₹50 Winnings. Enters ₹50 Tournament.
    - Expected Result:
      * Bucket precedence algorithm strictly deducts:
        1st: ₹20 Bonus (Max allowable bonus per tournament e.g. 10%-20%)
        2nd: ₹30 Deposit
        3rd: ₹0 Winnings
      * User's remaining balances are accurate: Deposit = ₹0, Bonus = ₹0, Winnings = ₹50.
      * Winnings bucket is preserved for withdrawal.

[ ] TC-03: DOUBLE-SPEND CONCURRENCY ATTACK (CRITICAL P0)
    - Action: User has ₹50 total balance. Send TWO simultaneous requests to join two ₹50 tournaments at the exact same millisecond.
    - Expected Result:
      * The database row lock (`SELECT ... FOR UPDATE`) and Redis idempotency lock allow exactly ONE tournament entry to succeed.
      * The second request FAILS with HTTP 400 "Insufficient balance".
      * Wallet balance NEVER goes negative (balance >= 0 invariant strictly maintained).

[ ] TC-04: WITHDRAWAL REQUEST INITIATION (`POST /wallet/withdraw`)
    - Action: Request to withdraw ₹500 to UPI VPA `player@upi`.
    - Expected Result:
      * Only `winningBalance` is eligible for withdrawal (Deposit and Bonus cannot be withdrawn).
      * Withdrawal amount must be <= `winningBalance`.
      * Transaction record created with status `PENDING` and amount is reserved in `in_flight_hold`.
