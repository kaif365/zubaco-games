3. NEWLY DISCOVERED ARCHITECTURAL DEFECTS
--------------------------------------------------------------------------------
3.1 [CRITICAL] Authoritative layer is a closed, unreachable loop.
    admin/admin.module.ts declares NO controllers. AdminControlPlaneService.
    execute() is the sole consumer of the orchestrator, ledger, enforcement
    engine and event bus, yet nothing invokes execute() (no controller, no cron,
    no internal caller). Result: the entire post-hardening authoritative surface
    is dead code at runtime. RBAC, idempotency and the immutable admin:audit
    trail never execute because no request reaches them.

3.2 [CRITICAL] Dual live control planes now coexist (divergence risk).
    Money:      live = WalletService.creditPrize / requestWithdrawal /
                deductEntryFee / creditReferralBonus (direct Decimal writes);
                dormant = WalletLedgerService.post.
    Enforcement: live = anti-cheat.service direct `is_banned:true` writes
                [anti-cheat.service.ts:144 auto, :269 admin-ban, :282 banUser];
                dormant = EnforcementService.enforce (no leaderboard/stage/
                payout retraction ever runs on the live path).
    Tournament:  live = EliminationService.runElimination (direct);
                dormant = TournamentOrchestrator.advanceStage.
    Each pair has DIFFERENT idempotency/retraction semantics, so a partial
    future rollout will silently diverge on real money.

3.3 [HIGH] Enforcement engine absent from the detection path.
    anti-cheat.service.analyzeGameResult / flagRealtime / banUser still mutate
    user state directly and never call enforce(). The ACHEAT-001 promise (atomic
    score/leaderboard/qualification/payout retraction) does not occur for any
    automatically- or admin-detected cheat in the live path.

3.4 [HIGH] Event bus is 1/11 utilised.
    Only WALLET_CREDITED is ever published (from the unreachable admin path).
    game.completed, verification.passed/failed, tournament.progressed/completed,
    reward.eligible, payout.settled/reversed, anticheat.enforced, account.
    reviewed are NEVER emitted. InAppEventSubscriber is therefore effectively
    dormant; the outbox/DLQ machinery processes nothing.

3.5 [MEDIUM] Two independent EVERY_10_SECONDS Redis drains, mixed multi-instance
    safety. events/event-bus.service.ts drain() claims via zrem (multi-instance
    safe). webhook/webhook.service.ts processOutbox() guards only with an
    in-process `processing` boolean (NOT safe across replicas — duplicate
    delivery under horizontal scale). Pattern inconsistency; webhook path is the
    weaker of the two.

3.6 [MEDIUM] resolveRewardEligibility (is_banned filter) is unreachable, and no
    distributePrizes exists in the platform at all (grep: none). The ACHEAT-001
    "banned cheaters can still be paid" risk is therefore NOT closed on any live
    path; prize payout remains in WalletService.creditPrize with no is_banned
    gate.

--------------------------------------------------------------------------------
4.1 Three game submit engines still diverge. Lifecycle + verification run ONLY
    in game-session.service.submitResult. free-play.service (emitGameResult
    at :288) and tournament.service.submitTournamentResult (:320) keep their own
    submit/score/emit paths and bypass assertTransition + verification.verify.
    GAME-001/002 cover 1 of 3 engines.
4.2 No HTTP/cron entry point for the admin control plane → ADMIN-001..004
    foundations deliver no runtime RBAC/audit yet.
4.3 No cron/scheduler invokes TournamentOrchestrator.advanceStage; tournament
    progression on the platform has no live trigger through the new engine.
4.4 Wallet ledger not called by any live money mutation; reference_id is still
    not UNIQUE (no DB constraint), so the idempotency guarantee is advisory
    (Redis-lock + prior-row check) and not enforced at the storage layer.
4.5 Legacy WalletService.creditPrize ignores bonus bucket and TDS and is not
    routed through the ledger — financial correctness unchanged on the live path.
