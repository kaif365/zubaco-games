1. OBJECTIVE
--------------------------------------------------------------------------------
Close the #1 blocker from full_audit.txt (ROLLOUT-001): the authoritative
platform control layer (AdminControlPlaneService — RBAC gate, idempotency,
immutable audit, and delegation into the tournament orchestrator, wallet ledger,
anti-cheat enforcement, and event bus) was fully built but UNREACHABLE in the
live runtime because AdminModule exposed NO HTTP controller. Nothing in
production execution could ever call AdminControlPlaneService.execute().

This phase makes that layer reachable by adding the single missing HTTP entry
point, guarded by the enterprise service-identity guard, validated by the global
ValidationPipe, and wired into the module graph — without breaking any existing
API and while keeping the build green.

5. IMPLEMENTED FEATURES
--------------------------------------------------------------------------------
- Live HTTP entry point for the authoritative admin control plane:
      POST /api/v1/admin/control-plane/execute
  Accepts a validated command, builds AdminContext { adminId, role } and
  AdminCommand { action, requestId, target, reason, params }, and invokes
  AdminControlPlaneService.execute(). All authoritative behaviour (RBAC via
  ROLE_PERMISSIONS, Redis SETNX idempotency, immutable audit, delegation to
  orchestrator/ledger/enforcement/event-bus) now executes on a real request.

- Read-only audit-trail endpoint:
      GET /api/v1/admin/control-plane/audit?limit=N
  Returns the most-recent-first immutable audit entries (bounded 1..500).

- Service-to-service authentication on both routes via ServiceIdentityGuard
  (signed x-service-id / x-timestamp / x-nonce / x-signature; Redis nonce
  replay protection; legacy x-internal-api-key honored only while
  SERVICE_IDENTITY_ENFORCE !== 'true').

- Input validation through the existing global ValidationPipe
  (whitelist + forbidNonWhitelisted + transform), so unknown fields are
  rejected and enum/length constraints are enforced at the boundary.

--------------------------------------------------------------------------------
6. EXECUTION PATHS UPDATED
--------------------------------------------------------------------------------
NEW reachable path (did not previously exist end-to-end):

  HTTP POST /api/v1/admin/control-plane/execute
    -> ServiceIdentityGuard.canActivate()            (auth)
    -> ValidationPipe (ExecuteAdminCommandDto)        (validation)
    -> AdminControlPlaneController.execute()
    -> AdminControlPlaneService.execute(ctx, cmd)
         -> ROLE_PERMISSIONS RBAC check
         -> Redis SETNX idempotency lock (admin:req:<requestId>)
         -> dispatch():
              ADVANCE_STAGE      -> TournamentOrchestrator.advanceStage()
              RESOLVE_REWARDS    -> TournamentOrchestrator.resolveRewardEligibility()
              CREDIT_WALLET      -> WalletLedgerService.post(ADJUSTMENT)
                                    + EventBusService.publish(WALLET_CREDITED)
              REVERSE_PAYOUT     -> WalletLedgerService.post(PAYOUT_REVERSAL)
              ENFORCE_ANTI_CHEAT -> EnforcementService.enforce(confirmed:true)
              MARK_FOR_REVIEW    -> EnforcementService.enforce(confirmed:false)
         -> immutable audit (Redis zadd admin:audit)

  HTTP GET  /api/v1/admin/control-plane/audit
    -> ServiceIdentityGuard -> getAuditTrail() -> Redis zrevrange(admin:audit)

Before this phase these delegated pipelines were only invokable from other
internal callers; the admin authoritative entry was a dead service.

11. KNOWN LIMITATIONS
--------------------------------------------------------------------------------
- The acting admin's identity (adminId, role) is forwarded by the admin console
  over the trusted service channel. ServiceIdentityGuard authenticates the
  CALLING SERVICE; it does not authenticate the individual human operator. The
  server still independently re-enforces RBAC via ROLE_PERMISSIONS, so a forged
  role cannot exceed its allowed actions, but operator-level identity assurance
  depends on the admin console's own auth. A future phase could carry a signed
  operator assertion (e.g. JWT) end-to-end.
- No automated test covers the new route (the project ships with no test
  harness — see TEST-001). Verification here is compile + build + DI/route
  registration reasoning, not an executed integration test.
- The audit endpoint reads from Redis only; if the audit zset is trimmed/expired
  by external policy, older entries are not retrievable (by design — append-only
  cache, not a durable store).

14. ARCHITECTURE CHANGES (OLD -> NEW)
--------------------------------------------------------------------------------
OLD:
  AdminModule = { providers:[AdminControlPlaneService], exports:[...] }
  No controller. AdminControlPlaneService was a fully-built but ORPHAN service:
  no inbound edge from the HTTP layer; unreachable in production execution.

NEW:
  AdminModule = {
    controllers:[AdminControlPlaneController],
    providers:[AdminControlPlaneService, ServiceIdentityGuard],
    exports:[AdminControlPlaneService]
  }
  The control plane now has a single guarded HTTP front door. The module graph
  edge HTTP -> Controller -> AdminControlPlaneService -> (orchestrator | ledger |
  enforcement | event-bus) is closed and live.

16. SECURITY IMPACT
--------------------------------------------------------------------------------
POSITIVE / NEUTRAL:
- Both new routes require ServiceIdentityGuard (signed request, clock-skew
  window, single-use Redis nonce replay protection). No anonymous access.
- Global ValidationPipe (whitelist + forbidNonWhitelisted + transform) rejects
  unknown/extra fields and enforces enum + length bounds, reducing injection /
  over-posting surface.
- Authorization is enforced server-side by ROLE_PERMISSIONS inside execute();
  the wire-supplied role is an assertion that cannot escalate beyond its mapped
  actions. Denied attempts are audited (DENIED) before rejection.
- Idempotency lock (SETNX, 7-day TTL) prevents duplicate financial side effects
  from retries; failures release the lock for safe retry.
- No secrets are logged; no real-money table is written directly.
RESIDUAL:
- Operator-level (human) identity assurance is delegated to the admin console
  (see Known Limitations). Recommend SERVICE_IDENTITY_ENFORCE='true' in
  production to disable the legacy x-internal-api-key fallback.
