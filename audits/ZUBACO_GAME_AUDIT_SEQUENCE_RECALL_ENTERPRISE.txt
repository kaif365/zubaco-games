1) FINAL VERDICT
--------------------------------------------------------------------------------
NOT PRODUCTION-READY.

This is the most mature variant: real session microservice (Redis + HTTP fallback)
SessionGuard, Restate Virtual Objects keyed userId:stageId (prevents cross-user
forgery), SHA-256 chained sequence generation (strong, not the 32-bit hash), and
serverSeed via crypto.randomBytes. Validation is server-authoritative via the
Restate object. HOWEVER the realtime WS gateway authenticates by MOCKING a random
user (no JWT verification), so anyone can connect and play as a synthetic identity,
and a second legacy WS stub uses a dev-secret fallback. The validate DTO also has
unbounded arrays (DoS).
