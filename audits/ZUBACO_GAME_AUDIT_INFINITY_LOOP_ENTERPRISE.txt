3. LOCALIZED DEFECTS
--------------------------------------------------------------------------------
INFINITYLOOP-VAL-01 [High] — game:rotate:batch unbounded + unvalidated moves[]
  game.gateway.ts:503-516 validates only Array.isArray(payload.moves) — no max
  length, no per-move coordinate bound check. game-session.object.ts rotateTileBatch
  (~line 489) indexes board.currentGrid[move.r][move.c] directly. A huge moves[]
  is a DoS (synchronous loop + per-move validateSolution); out-of-range r/c writes
  NaN/undefined into the grid (corruption / throw). Single game:rotate validates
  coords; batch does not. Fix: cap moves[] (e.g. 200), bound r in 0..gridY-1 and
  c in 0..gridX-1 before applying.

INFINITYLOOP-VAL-02 [Medium] — Math.random() board ordering
  game.service.ts:74 shuffleBoardIds uses Math.random(); puzzle.service.ts:34
  preview seed also Math.random. Non-CSPRNG board sequence is predictable in a
  real-money game. Fix: crypto.randomInt for shuffleBoardIds.

INFINITYLOOP-VAL-03 [Medium] — dev-auth/test-auth admin-token mint guard
  /game/join + /test-auth/token mint LOGIN tokens and test-auth accepts userType
  (1 USER / 2 ADMIN), gated by config.security.enableDevAuth (ENABLE_DEV_AUTH===
  'true', default false; controllers conditionally registered in game.module.ts).
  Fail-safe today, but a single env misconfig → anonymous ADMIN token minting.
  Fix: never compile TestAuthController into prod; assert ENABLE_DEV_AUTH false in
  prod fail-fast.

INFINITYLOOP-VAL-04 [Low] — calcBoardScore unbounded time bonus
  game-session.object.ts:107 score = 10 + max(0, timeLimit - durationSec). Bonus
  is bounded by timeLimit (admin) but board.timeLimit is unvalidated upstream;
  document/clamp to a hard ceiling for money-path determinism.
