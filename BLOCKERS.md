# BLOCKERS.md — Strategic Blocker Backlog

Master backlog of strategic blockers that **cannot be safely fixed during the current audit**.

**Process rules**
- Audits do **not** stop for these blockers. Record here, then continue auditing/fixing remaining modules.
- Blockers are revisited **only after every module has been audited and fixed**.
- This file is updated automatically whenever a future audit discovers a blocker that cannot be safely resolved.

**Status legend:** `Deferred` · `Waiting for Tests` · `Waiting for Design Decision` · `Waiting for Infrastructure`
**Priority legend:** `Critical` · `High` · `Medium` · `Low`

| SCORE-002 | High | Waiting for Design Decision | Global game leaderboard has no durable single source of truth. `leaderboard.updateScore` writes a Redis zset (`lb:game:<type>:all-time`) ONLY — no durable DB write — while the DB fallback (`getGameLeaderboardFromDb`) reads `gameProgress.best_score`, which is written by the free-play engine ONLY. ## Module: Anti-Cheat / Fraud Prevention

| ID | Priority | Status | Description |
|----|----------|--------|-------------|
| ACHEAT-001 | Critical | Partially Resolved (platform foundation) | Authoritative transactional enforcement engine added: `anti-cheat/enforcement/` (`enforcement.types.ts` defines 10 EnforcementActions — invalidate session, reject completion, remove leaderboard score, remove tournament score/qualification, revoke ranking, prevent/reverse wallet payout, invalidate rewards, mark-for-review; `enforcement.service.ts` `EnforcementService.enforce` executes ALL DB retractions in one Prisma `$transaction` all-or-nothing — session→DISQUALIFIED+score 0, `StageEntry` total 0/rank null/eliminated, user ban+`refreshToken` purge — then post-commit removes Redis leaderboard score (`leaderboard.removeScore`) and emits `enforcement.reversal` webhook to trigger wallet payout reversal). Remaining: filter `is_banned` in `elimination.distributePrizes`, add `device_fingerprint`/`ip`/`moves_hash` capture on free-play/tournament paths, and call `enforce` from detectors across the 20 backends (depends on GAME-002/ACHEAT-002; spans 20 backends + money path). |
| ACHEAT-002 | Critical | Waiting for Design Decision | The strongest fraud signals are structurally inert on the real-money tournament path (and the free-play *level* path). Device fingerprinting (`upsertFingerprint`) and `session.device_fingerprint`/`ip_address` are populated ONLY by the generic internal `game-session` start; `free-play.startLevel` and `tournament.startTournamentGame` create sessions with null device/ip and never register a fingerprint, so `DEVICE_DUPLICATE` is dead and `detectIPCorrelation` (which only runs for `mode==='TOURNAMENT'`) never executes with data. Making tournament anti-cheat effective requires end-to-end capture + server-side validation of these signals across the 20 game backends (depends on GAME-002; redesign). |
