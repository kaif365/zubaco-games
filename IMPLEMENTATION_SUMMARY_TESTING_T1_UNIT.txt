highest-risk business logic: scoring (money-adjacent), tax/compliance money
math (GST, TDS), age-gating, provably-fair RNG determinism, tournament
elimination rules, and anti-cheat fraud detection.

NO test framework installed at all (no jest / ts-jest / @nestjs/testing / test
script). The task instruction to "reuse the existing testing framework" could
not be followed literally because none existed. A minimal, standard jest +
ts-jest toolchain was therefore installed as devDependencies (local, reversible,
no CI impact) so tests can actually run and be verified.

Result: 7 unit-test suites, 70 tests, ALL PASSING. Production build remains
GREEN (`npm run build` succeeds; spec files are excluded from the build via the
existing tsconfig.build.json). No production source file was modified — only
test files and test-only config were added.

5. UNIT TESTS ADDED  (70 tests total)
--------------------------------------------------------------------------------
ScoringService — 16 tests (pure, dependency-free)
  * Missing/null/factless metadata -> unvalidated zero-score fallback.
  * Score never negative; always integer-rounded (penalty clamping).
  * Sliding puzzle: 100/round + floor(10 * remaining/total) time bonus;
    no time data -> no bonus.
  * Reaction-time anti-exploit floor: <=5s solve -> 0; >5s -> window-time;
    not-completed -> 0; maze win base (50) added on top.
  * Spot-the-difference: wrong-click/hint penalties clamp at 0; config-driven
    base/penalties honoured.
  * Colour sorting: base + efficiency(<=25) + speed(<=10) capped at 100;
    incomplete -> 0.
  * Generic config-driven scorer: correct*pts - wrong*penalty; used as fallback
    for unknown game types.
  * maxScore resolution: configured max_score overrides derived max.

GstService — 6 tests (pure money math)
  * GST-inclusive extraction (128 -> base 100 / GST 28; 100 -> 78.13 / 21.87).
  * 2-decimal rounding + base+gst reconstitutes total.
  * Zero fee -> no NaN.
  * GST-exclusive (100 -> +28 -> 128); rounding of odd values.
  * Display breakdown fields match the inclusive calculation.

TdsService — 6 tests (Prisma-mocked money math)
  * 30% of withdrawal deducted when liability exceeds it.
  * Deduction capped at remaining liability.
  * TDS already paid this FY subtracted (idempotency across withdrawals).
  * Net winnings floored at 0 when entry fees exceed winnings.
  * 2-decimal rounding of TDS and net amount.
  * TDS summary sums records; valid financial-year string.

AgeVerificationService — 7 tests (Prisma-mocked, boundary-focused)
  * Under-age rejected (BadRequestException) with NO DB write.
  * Exactly 18 today (boundary) -> verified; DB updated age_verified=true.
  * 18th birthday one day away -> rejected (age counted as 17).
  * Clearly adult -> verified.
  * ensureAgeVerified gate: verified passes; unverified/absent user throws.

DeterministicRng / DeterministicRngService — 16 tests (pure, provably-fair)
  * Reproducibility: identical seed -> identical stream; different seed diverges.
  * uint32 range and float [0,1) invariants.
  * intBetween inclusive bounds; reaches both endpoints; degenerate max<=min
    -> returns min.
  * Deterministic Fisher-Yates shuffle; result is a true permutation.
  * pick returns an in-array element.
  * buildSeedMaterial "::" joining and empty-string defaults.
  * create() reproducibility; nonce change diverges.
  * fingerprint: stable 32-hex for equal values; differs on tamper.

EliminationService — 6 tests (Prisma-mocked, tournament rules)
  * Unified pool (post-bucketing): surviveCount = ceil(n*(1-pct)); marks
    ELIMINATED; closes stage.
  * Per-bucket (pre-bucketing): eliminates within each cohort separately.
  * Survivor count rounds up (ceil) so ties favour survival.
  * Ordering enforces score desc then time asc (faster-wins tiebreaker).
  * Empty field short-circuits (no transaction, no stage close).
  * Missing stage throws.

AntiCheatService.analyzeGameResult — 13 tests (Prisma+Enforcement mocked)
  * Legitimate result -> no flags, no persistence.
  * Impossible score (> theoretical max) -> CRITICAL.
  * Timing anomaly (faster than min human time, score>0) -> HIGH; zero score
    is NOT flagged.
  * Board fingerprint mismatch -> SESSION_TAMPERING CRITICAL.
  * Client score inflation past max(10, 25%) tolerance -> HIGH; within tolerance
    -> no flag.
  * Bot input cadence: >=6 sub-100ms intervals -> CRITICAL; 3-5 -> HIGH;
    near-zero-variance over >=10 inputs -> HIGH; human/short log -> none.
  * Auto-enforcement triggers at 3 critical flags (enforce + session sweep +
    refresh-token purge); below threshold -> no enforcement.

14. REMAINING UNIT TEST GAPS
--------------------------------------------------------------------------------
Honest list of what is NOT yet unit-tested and why:

- Wallet ledger (wallet/ledger/ledger.service.ts, ~25KB) and payment gateway:
  heavily transactional (prisma.$transaction, row locks, idempotency keys).
  Meaningful tests need substantial transaction/mock scaffolding or an
  integration harness; deferred to keep this phase honest (unit-only) rather
  than writing shallow mock-only assertions that don't exercise real logic.
- Tournament orchestration / state machine, reward-payout, free-play/energy,
  leaderboard aggregation: mostly Prisma orchestration; partial unit value only.
- Auth (auth.service, otp.service), guards (jwt/internal/service-identity),
  authorization decorators: depend on JWT/Passport/Redis wiring; better covered
  by integration tests with the Nest testing module + a Redis test double.
- Notifications, admin control-plane, webhook signing/retry, event bus: I/O and
  scheduling oriented; limited pure-logic surface.
- DTO validation (class-validator): validated at the framework boundary; better
  asserted via e2e/request-level tests than isolated unit tests.
- No coverage report / threshold gates were added (out of scope: "do not
  increase coverage artificially", "do not touch coverage reports").
