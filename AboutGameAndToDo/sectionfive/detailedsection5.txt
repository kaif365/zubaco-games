3. DETAILED TECHNICAL AUDIT CRITERIA & INVARIANTS
------------------------------------------------------------------------------------------------------------------------
- 5.1 WebSocket Gateway Resilience & Reconnection:
  * Gateway: NestJS WebSocket Gateway (Socket.IO with Redis Adapter for multi-node clustering).
  * Heartbeat: Active ping/pong heartbeats every 5 seconds; client disconnect detection.
  * Flaky Network Reconnection Grace Period:
    - On mobile Wi-Fi to 4G handover or transient disconnect, reserve match slot in Redis for 30 seconds.
    - If player reconnects within 30 seconds presenting valid `matchTicket`, resume active level and score state.
    - If 30-second window expires, transition match state to `FORFEIT` and lock final score.

- 5.2 Automated 5-Stage Tournament State Machine:
  * Strict Sequential State Machine:
    [DRAFT] -> [REGISTRATION_OPEN] -> [REGISTRATION_CLOSED] ->
    [STAGE_1_LIVE] -> [STAGE_1_TALLY] ->
    [STAGE_2_LIVE] -> [STAGE_2_TALLY] ->
    [STAGE_3_LIVE] -> [STAGE_3_TALLY] ->
    [STAGE_4_LIVE] -> [STAGE_4_TALLY] ->
    [STAGE_5_LIVE] -> [STAGE_5_TALLY] ->
    [PRIZE_CALCULATION] -> [PRIZE_DISTRIBUTED] -> [ARCHIVED].
  * Automated Stage Tally Execution:
    - Millisecond precision queue / cron timer monitors stage transitions.
    - Cut-off calculation: rank participants and mark `eliminated = true` for lower percentile.
    - Broadcast `STAGE_RESULTS` WebSocket event to all connected room participants.
    - Enforce mandatory 60-second rest/intermission timer before advancing to next stage.

- 5.3 Cohort Matchmaking & Percentile Elimination:
  * Scale Invariant: Large tournaments (e.g., 2,000+ players) partitioned into balanced cohorts of 50 to 100 players.
  * Consistent Hashing: Assign cohorts deterministically via hash of `userId + tournamentId` to eliminate DB hot-spots.
  * Elimination Gating: Percentile cut-offs applied per cohort or globally, advancing only the top qualifying tier.
  * Anti-Orphan Protection: Bracket consolidation ensures odd-count cohorts merge gracefully without orphaned players.

- 5.4 Leaderboard Precision & Microsecond Tie-Breakers:
  * Compound Score Formula: `CompoundScore = BaseScore + (TimeBonus / 10000)`.
  * Deterministic Tie-Breaking: When two players achieve the identical base score, the player with the faster
    completion timestamp / lower elapsed milliseconds mathematically ranks higher in Redis `ZADD`.
  * High-Throughput Read: Live ranking queries (`zrevrank`, `zrevrange`, `zscore`) execute in O(log N) in Redis.
