2. MATHEMATICAL & CONCURRENCY AUDIT FINDINGS
------------------------------------------------------------------------------------------------------------------------
1. Fixed Production Logic Bug in `ledger.service.ts:76`:
   - Prior code had `const isCredit = CREDIT_OPS.has(req.operation) || req.amount >= 0;`.
   - Because `amount` is always positive (>0), `isCredit` was erroneously evaluating to `true` for debit operations.
   - Fixed by removing the redundant `>= 0` condition and properly including `ADJUSTMENT` in `CREDIT_OPS`.
   - Debits now strictly subtract balance and trigger `Insufficient balance` checks as intended.

2. Anti-Double-Spend Concurrency Guarantee:
   - When multiple concurrent join requests arrive for a player with ₹50 balance:
     * Request 1 locks the wallet row via `SELECT * FROM "wallets" WHERE "user_id" = $1 FOR UPDATE`.
     * Request 1 executes deduction, commits, and reduces balance to ₹0.
     * Request 2 (queued on the row lock) executes next, reads the updated balance (₹0), and throws `Insufficient balance for entry fee`.
     * Verified mathematically and dynamically via unit test `proves anti-double-spend: sequential transaction serialization rejects second debit`.

3. Storage-Level & Redis Idempotency:
   - Redis `setnx` mutex blocks duplicate in-flight requests holding the same idempotency key (`ConflictException: Operation already in progress`).
   - PostgreSQL unique constraint on `ledger_key` prevents duplicate records, returning the original committed balance without re-applying.
