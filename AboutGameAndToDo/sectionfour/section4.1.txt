2. TECHNICAL ARCHITECTURE & MATHEMATICAL INVARIANTS CERTIFIED
------------------------------------------------------------------------------------------------------------------------
A. Indian Mobile (+91) Invariant:
   - All inbound phone strings (e.g., `9876543210`, `+919876543210`, `919876543210`, `09876543210`) are strictly
     normalized to canonical `+91${10-digits}` matching `/^[6-9]\d{9}$/`.
   - Any non-conforming or non-Indian format is rejected immediately with HTTP 400 `BadRequestException`.
   - Prevents duplicate account creation or fragmented user profiles for the same physical SIM card.

B. OTP Rate Limiting Invariant:
   - Redis atomic counter `otp_rate:${normalizedPhone}` with sliding/tumbling 600-second TTL (10 minutes).
   - Maximum 3 requests allowed per 10-minute window (`config.otp.rateLimitMax = 3`).
   - 4th request triggers HTTP 400 `BadRequestException`.

C. Token Family & Replay Attack Invalidation (OAuth 2.0 Security BCP):
   - Every login session mints a refresh token associated with a unique `familyId`.
   - On each rotation, the old refresh token is flagged as `isUsed: true` and a new refresh token is issued under the same `familyId`.
   - If a previously consumed refresh token is presented again (indicating token theft or replay), the system
     flags immediate breach detection:
     1. Marks the family revoked (`rt_family_revoked:${familyId}`).
     2. Deletes all active Redis tokens belonging to that family set.
     3. Evicts all active tokens from Postgres `refresh_tokens`.
     4. Rejects request with HTTP 401 `UnauthorizedException`.
   - Validated: 15/15 test suites passed (156/156 tests), clean production build (`nest build`).
