1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Zubaco is a multi-app monorepo, not a single service. It comprises:
  - zubaco-platform/ ............ central NestJS backend (auth, wallet,
                                  tournament, leaderboard, social, compliance,
                                  anti-cheat, events). CANONICAL, builds GREEN.
  - 20 game apps ................ each a Vite/React (1 Next.js) FRONTEND plus its
                                  own NestJS GAME BACKEND (per-game session/
                                  verification, metrics, e2e tests, k8s).
  - zubaco-admin-panel-repo/ .... Next.js admin frontend + NestJS admin backend.
  - zubaco-mobile/ .............. React Native player app (the intended
                                  production player client).
  - zubaco-web-lobby/ ........... EXPLICITLY TEMPORARY 3-file dev launcher (stub).
  - infrastructure/, docker/, .github/, redis/ ... IaC, containers, CI/CD.

The backend platform and the per-game backends are strong and largely complete.
Infrastructure-as-code, Docker, and CI/CD are extensive. HOWEVER the project is
NOT production-ready because of concrete, code-verified gaps:
  - The central platform backend has ZERO automated tests and no `test` script,
    yet CI claims to test it (false-green).
  - The MOBILE app (the stated production player client) renders PLACEHOLDER data
    on every main screen — 12+ TODOs; no real data fetching wired.
  - The ADMIN panel runs on MOCK data for flagged-users and dashboard, has a
    no-backend notifications page, and is MISSING KYC, withdrawal-approval,
    anti-cheat-review and audit-log UIs.
  - There is NO production web player app (only the temporary lobby stub).
  - 14 of 20 game frontends have no tests; games are not tested in CI.
  - Observability is instrumented (OTel/Prometheus/pino) but there is no metrics
    backend (no Prometheus/Grafana deployment) and no error tracking (no Sentry).
  - The repository carries ~3x duplicated copies of large portions of the code.

VERDICT: PROJECT NOT COMPLETE (full item list in Sections 11-14, roadmap in
MASTER_REMAINING_WORK_ROADMAP.txt).
