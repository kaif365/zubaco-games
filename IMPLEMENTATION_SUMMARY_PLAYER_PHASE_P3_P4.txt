--------------------------------------------------------------------------------
1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Phase P3+P4 completes the remaining Player App functionality: authentication
hardening (Google / Apple sign-in, silent login / session restore, automatic
token refresh with a single-flight interceptor, global unauthorized handling
and logout cleanup), a real backend-driven Profile screen (view + edit +
verification/KYC status), a fully functional Settings screen (notification
preferences, security/biometric lock, privacy & legal links, delete account,
logout), app-wide Analytics (global screen tracking + auth/profile/settings
events) reusing the existing analytics abstraction, Crash Reporting (global
JS error handler, unhandled promise rejection reporting, and a React error
boundary) reusing the existing crashReporting abstraction, and Push
Notifications (device registration, token refresh, foreground/background
handling, deep-link tap navigation) reusing the existing notification service
and backend push-token endpoint.

All work reuses existing abstractions (AuthContext, React Query, the `api`
client, navigation, theme tokens, analyticsService, crashReporting, biometric,
secureStorage). No analytics events, tokens, or user data were hardcoded.

5. AUTHENTICATION
--------------------------------------------------------------------------------
- Phone OTP: existing send/verify flow retained; verifyOtp now returns a typed
  AuthResult and login() persists tokens + attaches observability/push.
- Google Sign-In: native SDK → id_token → POST /auth/google → session.
- Apple Sign-In: native SDK (iOS) → identity_token (+name) → POST /auth/apple.
- Silent login / session restore: on launch, AuthContext reads the secure
  access token, restores the profile, and re-establishes analytics/crash/push
  identity.
- Refresh token flow / automatic refresh: the api client transparently calls
  POST /auth/refresh on a 401 (single-flight to avoid stampedes) and retries
  the original request once.
- Session expiration / unauthorized handling: a failed refresh triggers the
  global onSessionExpired callback → local logout → navigator returns to Login.
- Global auth error interceptor: centralized in ApiClient.request(); /auth/*
  endpoints are exempt from the refresh-retry loop to avoid recursion.
- Logout cleanup: revokes the refresh token server-side, clears keychain
  tokens, drops the in-memory bearer, clears push registration, resets crash
  user, and emits a logout analytics event.

6. PROFILE
--------------------------------------------------------------------------------
- View profile from GET /users/me (React Query cache key ['profile']).
- Edit profile (username, display_name, avatar_url) via PATCH /users/me,
  sending only changed fields; success invalidates ['profile'] and refreshes
  AuthContext user; emits PROFILE_UPDATED.
- Avatar "upload" is by image URL only — the backend exposes no binary upload
  endpoint (documented honestly in the UI hint and in section 16).
- DOB is displayed read-only: the backend UpdateProfileDto does NOT accept
  date_of_birth, so it is intentionally not editable here.
- Email / phone verification status shown via is_verified; age via
  age_verified; KYC via the separate wallet query (wallet.kyc_verified), since
  KYC is not part of the profile payload.
- Loading, error + retry, empty, and pull-to-refresh states implemented.

9. CRASH REPORTING
--------------------------------------------------------------------------------
Reuses the existing crashReporting abstraction (Sentry wrapper).
- Initialized once at app startup (initCrashReporting()).
- Global JS exception reporting: installGlobalErrorHandlers() wraps the RN
  global error handler and forwards fatal/non-fatal JS exceptions.
- Unhandled promise rejection reporting: promise rejection tracking forwards
  to captureException.
- React render errors: ErrorBoundary.componentDidCatch → captureException with
  a user-facing recovery UI.
- User context: crashReporting.setUser attached on login/restore, cleared on
  logout. Breadcrumbs added on every tracked analytics event.

--------------------------------------------------------------------------------
10. PUSH NOTIFICATIONS
--------------------------------------------------------------------------------
Reuses the existing notification service concept via a push facade
(react-native-push-notification, which bridges FCM on Android and APNS on iOS).
- Device registration: pushNotifications.configure() registers the device and,
  on token receipt, posts to POST /notifications/push-token
  { device_id, push_token, platform } (backend-supported).
- Token refresh: onRegister re-registers whenever the OS issues a new token.
- Foreground/background: onNotification handles both; emits PUSH_RECEIVED for
  passive receipt and PUSH_OPENED on user tap.
- Deep links / tap navigation: handleDeepLink() routes taps via navigationRef
  (wallet/deposit/withdrawal/prize → Wallet, referral → Referral,
  tournament/season → MainTabs, default → Notifications).
- Registration is authenticated: registerToken() runs after login and on
  session restore; clear() runs on logout.

13. SECURITY IMPROVEMENTS
--------------------------------------------------------------------------------
- Tokens continue to be stored via react-native-keychain (secureStorage), never
  in plain AsyncStorage.
- Single-flight refresh prevents token-refresh stampedes and race conditions.
- Auth endpoints are excluded from the refresh-retry loop, preventing infinite
  loops and accidental credential replay.
- Automatic session teardown on unrecoverable 401 avoids using stale/invalid
  credentials.
- Biometric gate required before enabling the biometric lock preference.
- Account deletion is confirmation-gated and delegates anonymization to the
  server (no client-side PII retention after logout).
- Native SDKs loaded via guarded requires so a missing/misconfigured native
  module cannot crash the JS bundle.
- No secrets hardcoded; Google web client id read from process.env.
